## The challenge

Build a project with Flagsmith. Use feature flags to ship it, and use Experimentation to find out which version wins.

1. **Create a flag:** a multivariate flag holds the versions to compare.
2. **Pick a metric:** the event that counts as success (click, sign-up).
3. **Split the traffic:** decide how many users join the test and how they are split.
4. **Ship the winner:** Flagsmith shows the win probability for each version. Roll out the winner with the same flag.

Setup shortcut: paste Flagsmith's setup prompt into Claude Code or any coding agent. It creates the flag, metric and experiment, and adds code to your app after you approve it.

Sample experiment: flag on 5.1%, flag off 4.2%, 94% chance that "on" wins.

## Judging scorecard (all tracks)

- **Use of Flagsmith:** Is it a core part? Do flags/experiments do real work?
- **Impact:** Solves a real problem? Would a developer or team use it?
- **Creativity:** Is the idea new, or does it take a familiar idea somewhere new?
- **Demo video:** Clearly shows the problem, what you built and how Flagsmith fits in.

### Per-track criteria

- **Track 01, Test Something Real:** a clear question to test; versions behind a flag; a metric from real events; results you can explain.
- **Track 02, AI Agents and Feature Flags:** uses Flagsmith CLI, API or MCP server; saves real time; a human approves changes; clear output.
- **Track 03, Build on Open Source Flagsmith:** self-hosted Flagsmith; integrations and plugins; developer tools; easy for others to reuse.

## FAQ

- **Need to know Flagsmith already?** No. The Resources tab has docs, a demo video and guides.
- **Must I use Flagsmith?** Yes, as a core part of the project.
- **Is Flagsmith free?** It is open source and can be self-hosted for free. Flagsmith Cloud also has a free start.
- **AI coding tools allowed?** Yes, but you must understand and explain what you built.
